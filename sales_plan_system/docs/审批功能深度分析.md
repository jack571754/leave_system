# 审批功能深度分析

> 销售计划提报系统 — 函数级审批流程技术文档
>
> 生成日期: 2026-03-28

---

## 一、架构总览

### 1.1 模块构成

```
core/approvals/          ← 审批核心模块（模型 + 服务 + 视图 + 选择器）
core/plans/services.py   ← 任务提交/撤回业务逻辑
core/permissions/        ← 权限门控（can_submit / can_approve / can_withdraw）
core/errors.py           ← 类型化异常（ApprovalPermissionError / PlanStatusError）
templates/approvals/     ← 7 个前端模板（中心 / 待审批 / 历史 / 详情 / 批量）
```

### 1.2 双审批体系

系统同时存在 **Legacy 销售计划审批** 和 **新任务审批** 两套体系：

```
┌──────────────────────────────────────────────────────────┐
│                     审批入口                               │
├────────────────────────┬─────────────────────────────────┤
│  Legacy 销售计划审批     │  新任务审批（PlanTask）          │
│  SalesPlan + Approval  │  PlanTask + TaskApproval        │
│  Record                │  Instance + TaskApprovalRecord  │
│                        │                                 │
│  两级固定审批链          │  多级可配置审批链                 │
│  (submitter.manager →  │  ApprovalFlow → 动态步骤解析     │
│   department.manager)  │  (store → org_unit → dept →     │
│                        │   global 优先级)                 │
├────────────────────────┴─────────────────────────────────┤
│               ApprovalService (统一服务层)                 │
│  approve_plan / reject_plan / approve_task /              │
│  reject_task_to_submitter / reject_task_to_previous      │
└──────────────────────────────────────────────────────────┘
```

### 1.3 数据模型关系

```
SalesPlan (legacy)          PlanCampaign (新)
     │                            │
     │ 1:N                        │ 1:N
     ▼                            ▼
ApprovalRecord              PlanTask (店铺任务)
                                  │
                                  │ 1:N
                                  ▼
                          TaskApprovalInstance (审批轮次)
                                  │
                                  │ 1:N
                                  ▼
                          TaskApprovalRecord (审批操作记录)

ApprovalFlow ──配置──→ 多级审批链 (JSON levels)
```

## 二、数据模型 — 字段级详解

### 2.1 ApprovalRecord（Legacy 审批记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| `plan` | FK → SalesPlan | 关联的销售计划 |
| `approver` | FK → User | 审批人 |
| `approval_level` | Integer | 审批层级 (1, 2, ...) |
| `action` | CharField | `approve` 通过 / `reject` 退回 |
| `comment` | TextField | 审批意见 |
| `created_at` | DateTime | 创建时间 |

### 2.2 ApprovalFlow（审批流程配置）

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | CharField(100) | 流程名称 |
| `flow_type` | CharField(50) | `sales_plan` / `plan_task` |
| `scope_type` | CharField(20) | `global` / `department` / `org_unit` / `store` |
| `department` | FK → Department (nullable) | 适用部门 |
| `org_unit` | FK → OrgUnit (nullable) | 适用组织 |
| `store` | FK → Store (nullable) | 适用店铺 |
| `levels` | JSONField | 审批层级配置 |
| `is_active` | Boolean | 是否启用 |

**levels JSON 结构示例：**

```json
[
  {"step": 1, "approver_type": "manager", "label": "直属上级审批"},
  {"step": 2, "approver_type": "org_unit_manager", "label": "组织负责人审批"},
  {"step": 3, "approver_type": "parent_manager", "label": "上级组织负责人审批"}
]
```

**支持的 approver_type：**

| 值 | 解析逻辑 |
|----|---------|
| `manager` / `direct_manager` | `task.assignee.manager` |
| `org_unit_manager` | `task.org_unit.manager` |
| `parent_manager` | 沿组织树向上找到第一个有 manager 的祖先 |
| `user` | 按 `value` 字段指定用户 ID |
| `role` | 按 `value` 字段查找具有该角色的用户 |
| `admin` | 查找系统管理员角色用户 |

### 2.3 TaskApprovalInstance（任务审批实例）

| 字段 | 类型 | 说明 |
|------|------|------|
| `task` | FK → PlanTask | 关联的计划任务 |
| `round_no` | PositiveInteger | 审批轮次（每次重新提交递增） |
| `status` | CharField(20) | `pending` / `approved` / `rejected` / `withdrawn` |
| `current_step` | PositiveInteger | 当前审批步骤编号 |
| `submitter` | FK → User | 提交人 |
| `pending_approver` | FK → User (nullable) | 当前待审批人 |
| `submit_comment` | TextField | 提交说明 |
| `started_at` | DateTime | 发起时间 |
| `finished_at` | DateTime (nullable) | 结束时间 |
| `withdrawn_at` | DateTime (nullable) | 撤回时间 |

**唯一约束：** `(task, round_no)`

### 2.4 TaskApprovalRecord（任务审批记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| `instance` | FK → TaskApprovalInstance (nullable) | 关联审批实例 |
| `task` | FK → PlanTask | 关联计划任务 |
| `approver` | FK → User | 操作人 |
| `approval_level` | Integer | 审批层级 |
| `action` | CharField(30) | 操作类型（5种） |
| `comment` | TextField | 审批意见 |
| `created_at` | DateTime | 创建时间 |

**Action 枚举：**

| 值 | 中文 | 触发场景 |
|----|------|---------|
| `approve` | 通过 | 审批人点击"通过" |
| `reject_to_previous` | 驳回上一步 | 审批人点击"退回上一步" |
| `reject_to_submitter` | 驳回提交人 | 审批人点击"退回提交人" |
| `withdraw` | 撤回 | 提交人主动撤回 |
| `resubmit` | 重新提交 | 提交人修改后重新提交 |

## 三、服务层 — 函数级详解

### 3.1 ApprovalService（`core/approvals/services.py`）

单例：`approval_service = ApprovalService()`

#### `approve_plan(plan, approver, comment='') → ApprovalResult`

```
输入: SalesPlan, User, str
输出: ApprovalResult {success, plan, message, is_final_approval}

流程:
  1. plan.can_approve(approver)  → False 则抛 ApprovalPermissionError
  2. 检查 plan.status == PENDING  → 否则抛 PlanStatusError
  3. [transaction.atomic]
     a. 获取 current_level = plan.get_current_approval_level() 或 1
     b. 获取 max_level = plan.get_max_approval_level()
     c. 创建 ApprovalRecord(approve, current_level)
     d. 若 current_level >= max_level:
        → plan.status = APPROVED, plan.approved_at = now()
     e. 否则仅 plan.save(update_fields=['updated_at'])
  4. 返回 ApprovalResult
```

#### `reject_plan(plan, approver, comment='') → ApprovalResult`

```
输入: SalesPlan, User, str
输出: ApprovalResult {success, plan, message}

流程:
  1. plan.can_approve(approver) → False 则抛 ApprovalPermissionError
  2. [transaction.atomic]
     a. 获取 current_level
     b. 创建 ApprovalRecord(reject, current_level)
     c. plan.status = REJECTED
  3. 返回 ApprovalResult
```

#### `approve_task(task, approver, comment='') → ApprovalResult`

```
输入: PlanTask, User, str
输出: ApprovalResult {success, task, instance, message, is_final_approval}

流程:
  1. task.can_approve(approver) → False 则抛 ApprovalPermissionError
  2. 检查 task.approval_status == PENDING
  3. 获取 instance = task.get_active_approval_instance()
     → 无或非 PENDING 则抛 PlanStatusError
  4. 获取 step_map = _get_step_map(task)  # {step_num: {step, approver, label}}
  5. current_step = instance.current_step
  6. [transaction.atomic]
     a. 创建 TaskApprovalRecord(approve, current_step)
     b. next_step = current_step + 1
     c. 若 step_map 中存在 next_step:
        → instance.current_step = next_step
        → instance.pending_approver = next_step_data['approver']
        → instance.save()
        → task.sync_from_instance(instance)
        → 返回 (is_final_approval=False)
     d. 否则 (已是最后一步):
        → instance.status = APPROVED
        → instance.pending_approver = None
        → instance.finished_at = now()
        → instance.save()
        → task.sync_from_instance(instance)
        → 返回 (is_final_approval=True)
```

#### `reject_task_to_submitter(task, approver, comment='') → ApprovalResult`

```
输入: PlanTask, User, str
输出: ApprovalResult {success, task, instance, message}

流程:
  1. task.can_approve(approver) → 权限检查
  2. 获取 instance → 状态检查
  3. [transaction.atomic]
     a. 创建 TaskApprovalRecord(reject_to_submitter, instance.current_step)
     b. instance.status = REJECTED
     c. instance.pending_approver = None
     d. instance.finished_at = now()
     e. instance.save()
     f. task.sync_from_instance(instance)
  4. 返回 ApprovalResult
```

#### `reject_task_to_previous(task, approver, comment='') → ApprovalResult`

```
输入: PlanTask, User, str
输出: ApprovalResult {success, task, instance, message}

流程:
  1. task.can_approve(approver) → 权限检查
  2. 获取 instance → 状态检查
  3. previous_step = max(instance.current_step - 1, 1)
  4. step_map 获取 previous_step_data
  5. 若 previous_step_data 不存在 → 降级调用 reject_task_to_submitter()
  6. [transaction.atomic]
     a. 创建 TaskApprovalRecord(reject_to_previous, instance.current_step)
     b. instance.current_step = previous_step
     c. instance.pending_approver = previous_step_data['approver']
     d. instance.save()
     e. task.sync_from_instance(instance)
  7. 返回 ApprovalResult
```

#### `_get_step_map(task) → dict`

```
输入: PlanTask
输出: {step_number: {'step': int, 'approver': User, 'label': str}}

实现: 调用 task.get_approval_steps() 并以 step 字段为 key 构建 dict
```

#### `get_pending_approvals(user) → (QuerySet, QuerySet)`

```
输入: User
输出: (SalesPlan QuerySet, PlanTask QuerySet)

实现:
  若 user.is_approver() → 返回两类的 pending 数据集
  否则 → 返回空 QuerySet
```

### 3.2 TaskService（`core/plans/services.py`）

单例：`task_service = TaskService()`

#### `submit_task(task, user, comment='') → TaskResult`

```
输入: PlanTask, User, str
输出: TaskResult {success, task, message}

流程:
  1. task.can_submit(user) → False 则抛 ValidationError
  2. steps = task.get_approval_steps() → 空则抛 ValidationError
  3. [transaction.atomic]
     a. next_round = (task.round_no or 0) + 1
     b. 创建 TaskApprovalInstance(
          task=task, round_no=next_round, status=PENDING,
          current_step=1, submitter=user,
          pending_approver=steps[0]['approver'],
          submit_comment=comment
        )
     c. 创建 TaskApprovalRecord(
          action=RESUBMIT, approval_level=0
        )
     d. 更新 task 字段:
        submitter=user, submitted_at, last_submitted_at
     e. task.sync_from_instance(instance)
     f. task.save()
  4. 返回 TaskResult
```

#### `withdraw_task(task, user, comment='') → TaskResult`

```
输入: PlanTask, User, str
输出: TaskResult {success, task, message}

流程:
  1. task.can_withdraw(user) → False 则抛 ValidationError
  2. 获取 instance = task.get_active_approval_instance()
  3. [transaction.atomic]
     a. instance.status = WITHDRAWN
     b. instance.pending_approver = None
     c. instance.withdrawn_at = now()
     d. instance.finished_at = now()
     e. instance.save()
     f. 创建 TaskApprovalRecord(action=WITHDRAW)
     g. task.last_withdrawn_at = now()
     h. task.sync_from_instance(instance)
     i. task.save()
  4. 返回 TaskResult
```

### 3.3 ApprovalFlow 模型方法（`core/approvals/models.py`）

#### `get_approver_for_level(level, submitter) → User | None`

```
输入: int, User
输出: User 或 None

实现:
  1. 从 self.levels 中匹配 level/step
  2. 若 level==1 且 submitter.manager 存在 → 直接返回
  3. 按 approver_type 解析:
     - 'user' → User.objects.get(pk=value)
     - 'role' → User.objects.filter(role=value)
     - role 字段 → 按部门过滤
  4. 无匹配返回 None
```

#### `get_applicable_for_task(task) → ApprovalFlow | None`（classmethod）

```
输入: PlanTask
输出: ApprovalFlow 或 None

匹配优先级（从高到低）:
  1. STORE 级: scope_type=store, store_id=task.store_id
  2. ORG_UNIT 级: 沿 org_unit 树向上查找（含当前节点）
  3. DEPARTMENT 级: org_unit 的 parent 对应的部门级流程
  4. GLOBAL 级: scope_type=global 的兜底流程
```

#### `get_steps_for_task(task) → list[dict]`

```
输入: PlanTask
输出: [{'step': int, 'approver': User, 'label': str}, ...]

实现:
  1. 遍历 self.levels，逐个解析 approver_type:
     - manager / direct_manager → task.assignee.manager
     - org_unit_manager → task.org_unit.manager
     - parent_manager → 沿 parent 链向上找有 manager 的祖先
     - user → User.objects.get(pk=value)
     - role → User.objects.filter(role=value)
     - admin → User.objects.filter(role=ADMIN)
  2. 去重（已出现的 User 不重复添加）
  3. 返回解析后的步骤列表
```

### 3.4 Selectors（`core/approvals/selectors.py`）

输入: User

逻辑:
  1. 权限检查: has_perm('approvals.instance.view') 或已认证
  2. 过滤: submitter=user, store_id ∈ authorized_store_ids
```

#### `approval_history_for_user(user) → QuerySet[TaskApprovalRecord]`

```
输入: User
输出: 审批历史记录 QuerySet

逻辑:

### 3.5 权限门控（`core/permissions/services.py`）

#### `can_submit_task(user, task) → bool`

```
  1. task 无 items → False
  2. 有 'plans.task.submit' 权限 → campaign.is_open()
  3. 否则 → can_edit_task() (检查编辑窗口 + 审批状态)
```

#### `can_withdraw_task(user, task) → bool`

```
  1. approval_status ≠ PENDING → False
  2. 有 'plans.task.withdraw' 权限 → True
  3. 否则 → user.id == task.submitter_id
```

#### `can_approve_task(user, task) → bool`

```
  1. approval_status ≠ PENDING → False
  2. 有 'approvals.instance.approve' 权限 → True (检查 deny)
  3. 否则 → task.pending_approver_id == user.id
```

#### `can_view_approval_instance(user, instance) → bool`

```
  有 'approvals.instance.view' 或 'approvals.instance.approve' 权限
  或 user == instance.submitter 或 user == instance.pending_approver
```

### 3.6 PlanTask 模型审批方法（`core/plans/models.py`）

#### `sync_from_instance(instance) → None`

```
将 TaskApprovalInstance 的状态同步回 PlanTask:

  instance.status    → task.status          + task.approval_status
  instance.round_no  → task.round_no
  instance.current_step → task.current_step
  instance.pending_approver → task.pending_approver

  状态映射:
    APPROVED   → status=APPROVED, approval_status=APPROVED, approved_at=now()
    REJECTED   → status=REJECTED, approval_status=REJECTED, pending_approver=None
    WITHDRAWN  → status=WITHDRAWN, approval_status=WITHDRAWN, pending_approver=None
    其他       → status=SUBMITTED, approval_status=PENDING
```

#### `get_approval_steps() → list[dict]`

```
  1. 获取 ApprovalFlow = get_approval_flow()
  2. 若 flow 存在 → flow.get_steps_for_task(self)
  3. 否则回退到组织链手工构建:
     a. assignee.manager → "Direct manager"
     b. org_unit.manager → "Org unit manager"
     c. org_unit.parent 链上的 manager → "{name} manager"
     d. 最终兜底 → 系统管理员 "System admin"
  4. 全程按 user.pk 去重
```

#### `pending_for_approver(user) → QuerySet`（classmethod）

```
  1. 基础过滤: approval_status=PENDING, store_id ∈ authorized_store_ids
  2. 有 'approvals.instance.approve' 权限 → 返回全部
  3. ADMIN 角色 → 返回全部
  4. 否则 → 过滤 pending_approver=user
```

### 4.2 视图函数详解

#### `approval_center(request)`

```
上下文:
  - pending_instances: 最近5条待审批实例
  - pending_count: 待审批总数
  - my_pending_requests: 我的待审批请求数
  - my_requests_preview: 最近5条我的请求
模板: approvals/center.html
```

#### `pending_approvals(request)`

```
权限: has_perm('approvals.instance.approve') 或 is_approver()
过滤: ?month=YYYY-MM（按计划月份过滤）
上下文:
  - instances: 待审批实例列表（按 -created_at 排序）
  - current_month: 当前筛选月份
模板: approvals/pending.html
```

#### `approve_task(request, task_id)`

```
方法: POST only
参数: comment (POST body)
流程:
  1. 获取 task（select_related campaign, store）
  2. approval_service.approve_task(task, user, comment)
  3. 成功 → messages.success → redirect pending
  4. 失败 → messages.error → redirect pending
```

#### `reject_task(request, task_id)`

```
方法: POST only
参数: comment, action (POST body, action='reject_to_submitter'|'reject_to_previous')
流程:
  1. 获取 task
  2. 根据 action 分发:
     - 'reject_to_previous' → approval_service.reject_task_to_previous()
     - 其他 → approval_service.reject_task_to_submitter()
  3. 成功/失败 → messages → redirect pending
```

#### `batch_approve(request)`

```
方法: POST only
参数: task_ids[] (POST body checkbox 列表), comment
流程:
  1. 解析 task_ids = [int(v) for v in POST.getlist('task_ids')]
  2. 遍历 PlanTask.objects.filter(pk__in=ids)
  3. 逐个调用 approval_service.approve_task()
  4. 统计 success/failed 计数
  5. messages → redirect pending
```

#### `batch_reject(request)`

```
方法: POST only
参数: task_ids[], action, comment
流程: 同 batch_approve，但分发 reject_task_to_previous / reject_task_to_submitter
```

#### `pending_count_api(request)`

```
方法: GET
权限: has_perm('approvals.instance.approve') 或 is_approver()
输出: JsonResponse({'count': int})
用途: 前端导航栏审批徽章轮询（每60秒）
```

## 五、完整审批状态机

### 5.1 PlanTask 审批状态流转

```
                    ┌────────────────────────────────────────┐
                    │                                        │
                    ▼                                        │
  ┌──────┐  submit  ┌──────────┐  approve   ┌─────────┐    │
  │ 草稿  │────────→│ 审批中    │──────────→│ 已通过   │    │
  │draft │         │ pending  │           │approved │    │
  └──────┘         └────┬─────┘           └─────────┘    │
     ▲                  │                                   │
     │            withdraw│                          reject │
     │                  │                                  │
     │                  ▼                                  │
     │            ┌──────────┐                             │
     │            │ 已撤回    │                             │
     │            │withdrawn │                             │
     │            └────┬─────┘                             │
     │                 │                                   │
     │            resubmit (新的 round_no)                  │
     │                 │                                   │
     │                 └─────→ 回到 "审批中" ──────────────┘
     │                                                    │
     │             reject_to_submitter                    │
     │<───────────────────────────────────────────────────┘
     │
     │             reject_to_submitter
     │<──────────────────────────┐
     │                           │
     │  ┌──────────┐  reject    │
     └──│ 已驳回    │←───────────┘
        │rejected  │
        └──────────┘
```

### 5.2 TaskApprovalInstance 状态流转

```
  PENDING ──approve(最后一步)──→ APPROVED
  PENDING ──approve(中间步骤)──→ PENDING (step+1, 换审批人)
  PENDING ──reject_to_submitter──→ REJECTED
  PENDING ──reject_to_previous──→ PENDING (step-1, 换审批人)
  PENDING ──withdraw──→ WITHDRAWN
```

### 5.3 TaskApprovalRecord 动作时序

```
提交:    RESUBMIT (approval_level=0, by submitter)
审批:    APPROVE / REJECT_TO_PREVIOUS / REJECT_TO_SUBMITTER (by approver)
撤回:    WITHDRAW (by submitter)
重新提交: RESUBMIT (approval_level=0, by submitter, 新 instance)
```

## 六、审批链解析算法

### 6.1 流程匹配（优先级从高到低）

```
1. STORE 级    → store_id 完全匹配
2. ORG_UNIT 级  → 沿 org_unit.parent 链向上查找（BFS）
3. DEPARTMENT 级 → org_unit.parent 对应的部门级
4. GLOBAL 级    → 兜底全局流程
```

### 6.2 审批人解析（从 levels JSON 到 User 对象）

```
对于 levels 中的每个 step:
  ├── approver_type = "manager"
  │   └── task.assignee.manager
  ├── approver_type = "org_unit_manager"
  │   └── task.org_unit.manager
  ├── approver_type = "parent_manager"
  │   └── 沿 org_unit.parent 链找第一个有 manager 的祖先
  ├── approver_type = "user", value = user_id
  │   └── User.objects.get(pk=value)
  ├── approver_type = "role", value = role_code
  │   └── User.objects.filter(role=value).first()
  └── approver_type = "admin"
      └── User.objects.filter(role=ADMIN).first()

去重规则: 同一 User 只出现一次（seen_user_ids set）
```

### 6.3 回退链（无 ApprovalFlow 时的兜底）

```
step 1: task.assignee.manager          → "Direct manager"
step 2: task.org_unit.manager          → "Org unit manager"
step 3+: org_unit.parent.manager 链    → "{name} manager"
最终兜底: Admin 角色                    → "System admin"
```

## 十一、核心调用链速查

### 提交审批

```
POST /plans/tasks/<pk>/submit/
  → plans.views.submit_task()
    → task.can_submit(user)                    # 权限检查
      → permissions_service.can_submit_task()
    → task_service.submit_task()
      → task.get_approval_steps()             # 解析审批链
        → ApprovalFlow.get_applicable_for_task()
        → flow.get_steps_for_task()
      → TaskApprovalInstance.objects.create() # 创建实例
      → TaskApprovalRecord.objects.create()   # 记录 RESUBMIT
      → task.sync_from_instance()             # 同步状态
```

### 通过审批

```
POST /approvals/tasks/<pk>/approve/
  → approvals.views.approve_task()
    → task.can_approve(user)                   # 权限检查
      → permissions_service.can_approve_task()
    → approval_service.approve_task()
      → _get_step_map(task)                   # 获取步骤映射
      → TaskApprovalRecord.objects.create()   # 记录 APPROVE
      → if next_step exists:
          instance.current_step += 1           # 流转下一步
          instance.pending_approver = next     # 更换审批人
        else:
          instance.status = APPROVED           # 最终通过
      → task.sync_from_instance()             # 同步状态
```

### 驳回到上一步

```
POST /approvals/tasks/<pk>/reject/
  → approvals.views.reject_task()
    → approval_service.reject_task_to_previous()
      → previous_step = current_step - 1
      → if no previous → reject_task_to_submitter()   # 降级
      → TaskApprovalRecord(reject_to_previous)
      → instance.current_step = previous_step
      → instance.pending_approver = previous_approver
      → task.sync_from_instance()
```

### 批量通过

```
POST /approvals/batch-approve/
  → approvals.views.batch_approve()
    → 解析 task_ids[] from POST
    → for each task:
        approval_service.approve_task()
    → 统计 success/failed
    → messages → redirect
```

## 十二、待优化项

| 优先级 | 问题 | 建议 |
|--------|------|------|
| P0 | 批量操作无幂等保护 | 添加 `instance.status` 前置检查，避免并发重复审批 |
| P1 | 审批链解析无缓存 | `get_approval_steps()` 每次查 DB + 解析 JSON，应在实例中缓存 |
| P1 | 无审批通知机制 | 审批流转后无消息通知（飞书/邮件/站内信） |
| P2 | Legacy 审批与新审批并存 | SalesPlan 审批应迁移到 ApprovalFlow 体系 |
| P2 | 无审批超时机制 | 审批实例无超时自动升级/提醒功能 |
| P3 | 审批记录查询无分页 | `approval_history_for_user` 无分页，大数据量有性能风险 |
